# Restaurant Guide design decisions

Current implementation choices based on the approved [requirements](requirements.md), retained wireframes and requested prototype refinements. These choices do not rewrite the proposal's original requirement IDs or wording.

| Item | Saved evidence | Current decision and boundary |
| --- | --- | --- |
| Rating value | FR-07 specifies a “1-5 star integer rating”; the student explicitly requested dragging directly across the stars and fractional values. Figma illustrates 4.5/5. | Implement half-star increments with enlarged draggable stars, numeric value and Save/Cancel. Add starts unrated; existing records retain their ratings. The model uses `Float`, and `restaurants-v3` UI state restores v2/legacy integer values. The user's request authorizes this prototype choice; the source requirement is not silently changed. |
| Phone number(s) | FR-06 allows phone number(s); the retained form shows one Phone field. | Keep `phone:String` for the prototype, with multiple numbers entered on separate lines, an Add phone number control and invalid-number feedback. These are native extensions; no retained multiple-phone frame exists. Durable storage representation remains later work. |
| Address entry | FR-08 requires separated fields and/or formatting assistance; Figma shows “Street address, city and postal code.” | Retain that field/prompt and add an address-details dialog with separated fields and Canadian postal-code formatting. This is a native extension, not an exported Figma variant; it does not geocode the address. |
| User-defined tags | FR-10 permits selecting one or more tags; the proposal declares `tags:String`. The accepted demo uses any-selected-category matching (OR). | Store tags as a session `List<String>`, add/remove tags through the shared form and deduplicate without case. List filters are selectable; Details tags remain read-only outlined labels. Search combines with selected-tag matching using AND. |
| Photos, captions and visit notes | The student explicitly requested these additions; they are absent from the original FR attributes. Existing menu photos are illustrative. | Include cover replacement/removal, album add/remove, optional captions for chosen photos and visit notes in the shared Add/Edit draft. Form Back discards draft changes; Save updates the selected/new record. Cover references and album/caption references are separate model fields. Durable photo storage remains later work. |
| Gallery zoom | The student's supplied viewer reference includes −/percentage/+ controls; zoom was explicitly requested for the final prototype pass. No named retained zoom Figma frame exists. | Preserve the black gallery and add 100–300% pinch/button zoom, percentage reset and bounded panning for bundled/URI images. One finger swipes at fit and pans while enlarged. Arrows/thumbnails select another image at 100%; Close/hardware Back return to the same Details. Loading/unavailable images disable zoom. Long captions remain scrollable; short windows use compact spacing. Existing image resolution limits still apply. |
| About styling | FR-19 requires application/project information and all team names. Existing labels and names come from the approved proposal; no named retained About Figma frame exists. | Use the shared compact purple toolbar, a lavender information panel and a white team panel with soft borders, rounded corners and scrollable content. Retain all four names and the existing purpose text. Toolbar/hardware Back preserve List search and selected tags. |
| Google Maps setup | The proposal names Google Maps SDK/API and location permissions. The accepted navigation is Details → internal Full-Screen Map → Get directions → Google Maps. | The compact native map layout uses selected static captures, the saved address and a destination-only directions URL. Its address information scrolls independently of Get directions. No named Figma map frame is retained. Live map configuration, geocoding, app-obtained current location and denied/unavailable-location feedback remain unimplemented. Keep future credentials outside version control. |

The shared form follows Add **52:213**, Edit **50:166** and rating overlay **76:271**, retaining labels, floating fields, 12dp input corners and the 16dp photo-to-description gap. **+ photo** sits beside short albums with an 8dp gap, starts at the left when empty and remains visible while long albums scroll.

Search is a trimmed, case-insensitive name substring match. Selected tags match any selected category; the name query and tag result combine with AND. All clears tags while preserving the query; Clear search and filters clears both. A custom tag named All displays “(tag)” to distinguish it from reset.

Remaining functional work: durable records/photos, live Maps/geocoding, current-location permission/error handling and verified external email/navigation handoffs. Current saved UI state is not durable storage.

Device tests use Espresso 3.7.0 for compatibility with the API 37 fixture; see the [AndroidX Test release notes](https://developer.android.com/jetpack/androidx/releases/test#espresso-3.7.0).
